# SmartQ 编码规范

本文是代码结构、命名、职责和质量门禁的项目约定。配置文件可以自动执行的规则；本文补充需要开发者判断的设计原则。

## 代码放置

- `apps/web/src/app` 放页面框架、路由和全局状态；具体业务页面与状态放 `features/<功能名>`。
- 一个功能的页面、展示模块、数据请求、状态处理和类型尽量放在同一功能目录，调用方从少量明确的导出入口使用它。
- `shared` 只放两个或更多功能实际共用的通用代码。抽象应解决已经出现的重复或变化，不为假设中的复用预先增加层次。
- `apps/api/src/http` 负责协议解析、状态码和响应；`application` 编排用例；`infrastructure` 实现 MySQL、SQLite、模型等外部适配器；`domain` 放不依赖框架的业务规则。
- 路由处理器保持薄：完成输入校验后调用用例，再映射成 HTTP/SSE 响应。SQL、密钥加解密和业务决策各自归属基础设施或业务模块。
- `packages/contracts` 只放前后端需要共享的结构、运行时校验和类型，不放页面或数据库实现。

## 模块与界面

- 每个模块有清楚的调用接口和单一职责。把复杂行为收进一个稳定接口里，让调用者不必了解内部步骤。
- 页面模块负责编排区域；独立表单、表格、对话卡片、弹窗等有自己的交互或状态时，拆成可单独理解的组件。
- 展示组件通过属性接收数据和动作；网络请求、缓存/加载状态和错误转换集中在功能 API 模块或自定义 Hook。
- 组件拆分依据职责、变化原因和复用位置，不按固定行数拆分。避免大组件承载页面、请求、数据转换和错误处理的全部逻辑。
- 后端外部依赖通过适配器访问。应用用例接收依赖并编排行为，不在路由或页面中直接创建数据库连接。
- 所有页面必须使用固定视口的应用外壳。`html`、`body`、`#root` 和 `.app-shell` 不产生页面级滚动；模块长内容由 `.page-content` 在内部纵向滚动，侧栏与顶栏保持固定。新增模块后需在浏览器中检查实际滚动位置，并通过 `pnpm check:layout`。

## 类型与错误

- 所有外部输入在入口校验：HTTP 请求、模型输出、环境变量和数据库元数据不能因 TypeScript 类型声明而被视为可信。
- 业务数据优先使用明确的联合类型和 `unknown`；新增 `any` 需要先证明边界无法表达，默认规则会拒绝 `any`。
- 错误在离开所属模块前转换为可理解、可处理的结果；用户提示不暴露密码、密文、SQL 参数、堆栈或供应商原始响应。
- 数据库标识符只来自已读取并验证过的结构；查询值使用参数绑定。前端不得拼接 SQL。
- 公共函数的参数、返回值和错误约定应明确。类型不能表达的前置条件、顺序或副作用，写在靠近接口的简短注释中。

## 命名与文件

- 文件及变量使用 `camelCase`，React 组件和类型使用 `PascalCase`，常量使用 `UPPER_SNAKE_CASE` 仅限固定配置值。
- React 组件放在 `components/` 并以 `.tsx` 结尾；自定义 Hook 使用 `use` 前缀；纯计算模块优先使用 `.ts`。
- 同一功能内使用相对路径；跨功能引用通过稳定的公共入口，不穿透到其他功能的内部组件或状态文件。
- 注释解释原因、约束和不明显的取舍；避免复述代码。用户界面文本和面向中国读者的项目说明使用简体中文。

## 质量门禁

- `pnpm format` 统一格式；`pnpm format:check` 检查格式，不通过手工争论格式差异。
- `pnpm lint` 使用 ESLint 检查全仓库 JavaScript、TypeScript、React Hooks 和类型安全规则，并将警告视为失败；`pnpm lint:css` 使用 Stylelint 检查 CSS。
- `pnpm check:layout` 检查固定视口和模块内滚动所需的全局 CSS 约定，防止页面滚动边界被意外移除。
- `pnpm check:shell` 检查演示数据库 Bash 脚本语法；`pnpm check:compose` 检查 Compose 配置但不启动容器；`pnpm build` 检查各工作区 TypeScript、CSS 处理和生产构建。
- 每次代码或配置改动后执行 `pnpm check:diagnostics`；交付前执行 `pnpm quality`。新增文件类型时，先确定编辑器诊断来源，再将检查接入诊断命令与 CI。
- `pnpm test` 运行 Vitest 回归用例；优先覆盖请求边界、业务规则和状态转换，不为尚未实现的流程写模拟性测试。
- 前端 TypeScript 编辑器诊断使用 `apps/web/package.json` 锁定的工作区版本；交付时确保可读取的问题面板没有工作区错误。
- `pnpm quality` 检查运行环境、OpenSpec 变更、全仓库静态诊断和回归用例；依赖变更应通过 pnpm 更新工作区清单和锁文件。
