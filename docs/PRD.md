## 1. 产品定位

SmartQ 是一个用于学习和面试展示的自然语言数据分析应用。管理员可以连接数据库选取一张表，也可以导入表格文件创建问数资源；用户选择资源后用自然语言提问，系统解释问题、生成并执行受控查询，再呈现数据、图表和查询过程。

它要让面试官看明白三件事：

1. **小 Q 问数是什么**：把业务语言转换成有数据依据的查询和分析结果。
2. **难点在哪里**：字段语义和指标口径、问题歧义与上下文、查询安全与结果可信。
3. **前端做了什么**：管理复杂对话状态，把澄清、执行进度、SQL、数据表和图表组织成连贯、可解释的交互。

## 2. 核心演示链路

**连接数据库或导入表格文件 → 选择一张表 → 配置问数语义 → 用户选择该资源并提问 → 歧义澄清 → 生成并执行只读查询 → 展示解释、SQL、表格和图表 → 基于上一轮继续追问。**

一个演示例子：管理员把 `orders` 表发布为“订单数据”，将 `amount` 配置成“销售金额/销售额”、默认聚合为求和，并设置“按城市统计销售额”为推荐问题。用户问“今年各城市销售额怎么样”，系统识别时间、维度和指标，生成 SQL；用户看到执行条件、SQL、结果表和柱状图，再追问“哪个城市最高”。

## 3. 本期范围

本期交付一个完整的纵向切片，限制产品复杂度：一个本地演示工作区、MySQL 单表直连或本地表格导入、一个问题对应一个问数资源/单表、一个默认大模型配置。MySQL 业务数据只读直连；导入文件数据保存在本地 SQLite 中并按只读方式查询；界面显示数据来源和最近一次查询时间。

### 3.1 必须实现

| 模块           | 本期能力                                                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 数据接入       | 新建/测试一个数据库连接并浏览表；或导入 `.xlsx`、`.xls`、`.csv`、`.tsv` 文件、预览工作表；从其中选择一张表创建问数资源                      |
| 问数语义配置   | 为资源/字段配置业务名称、描述、字段类型、维度或指标、单位、默认聚合、同义词；保存 1–4 条推荐问题                                            |
| 模型配置       | 管理员配置一个模型服务的地址、模型名称和密钥；密钥遮蔽；提供连通性测试和默认配置                                                            |
| 自然语言问数   | 选择一个资源提问；解析指标、维度、筛选和时间；关键信息不清楚时追问确认；在会话内保留上下文并支持追问                                        |
| 结果呈现       | 展示简要分析说明、实际查询条件、执行 SQL、结果表；按数据形态提供指标卡、柱状图或折线图，并能在适用图表间切换                                |
| 会话           | 展示当前会话消息和简易历史会话；支持新建会话和继续追问                                                                                      |
| 基础安全与调试 | 连接凭据不回显；数据库使用只读账号；执行前检查生成查询，只允许已配置资源和字段，限制返回行数与执行时间；记录问题、SQL、状态、耗时和错误阶段 |

### 3.2 明确不做

以下能力不属于本学习项目的实现范围：多租户/企业组织架构、复杂 RBAC/用户组与行列级权限管理、跨表关联和跨资源自动选表、企业级知识库批量导入导出、正则改写、模型多供应商路由、语音和移动端、趋势预测/波动归因、运营分析大盘、外部系统嵌入、BI 仪表板设计、计费订阅和生产级部署运维。

这些能力在 Quick BI 参考产品中存在或属于企业级扩展，但对本项目证明核心概念与前端工程能力贡献较低，会显著扩展实现面。[调研笔记](research/small-q-chat-bi-research.md)

## 4. 用户和页面

本期只区分两类演示角色：

- **管理员**：接入数据库或导入表格、选择表、配置模型和问数语义、运行配置调试。
- **问数用户**：选择已发布资源、提问、确认澄清、查看和追问结果。

通过页面内角色切换器模拟这两类使用场景；不做真实登录、身份认证或服务端角色授权。

页面控制在四个主要工作区：

1. **问数工作台**：资源选择器、推荐问题、对话消息、输入区和执行状态。
2. **结果详情**：解释文本、筛选条件/指标/维度、SQL 折叠面板、数据表、图表切换。
3. **数据配置**：连接测试、库表浏览、文件上传和工作表预览、字段语义表单、推荐问题、调试提问。
4. **模型配置**：单个模型的参数表单、密钥遮蔽、测试结果和启用状态。

## 5. 关键行为规格

详细的可验收行为以 `openspec/changes/learning-mvp/specs/` 下的规格文件为准。PRD 只固定产品边界和演示目标。

### 5.1 数据配置

- 连接测试失败时显示可读错误，不得将失败连接标记为可用。
- 资源发布前必须能预览表结构，并给每个可问字段配置业务语义；无语义字段可设为不可问。
- 数据表或字段结构变化后，后台能提示资源配置需复核。

### 5.2 问数对话

- 用户可以明确选择一个资源发问；本期不做全库自动找表。
- 对话结果至少能说明“使用了什么指标、哪些过滤条件、查询了哪个资源”。
- 当时间、指标或过滤对象存在多种合理解释时，先呈现选择项；确认后再执行。
- 后续问题继承当前会话上下文；切换会话后不得串用旧上下文。
- 查询失败时显示失败阶段和下一步建议，不生成貌似真实的数据答案。

### 5.3 安全边界

- 大模型只负责输出结构化 JSON 查询计划，不生成或执行 SQL；查询执行层必须独立检查资源、字段、聚合、筛选、行数和超时，再由服务端生成参数化 SQL。
- 本期使用只读数据库账号；仅允许对一个已配置资源执行单表 `SELECT`，拒绝写入、DDL、未配置表/字段和多语句。
- SQL 展示用于解释与学习；实际查询仍由服务端执行，前端不能直接连接数据库。
- 演示服务默认仅绑定本机；页面角色切换只控制演示入口，不构成授权边界。

## 6. 前端重点与面试讲解

### 6.1 需要展示的前端工程点

- **对话状态管理**：新问题、澄清中、查询中、成功、空结果、失败和取消；防止快速切换会话时旧请求覆盖新状态。
- **结构化消息渲染**：同一条回答可以包含文本、澄清选项、SQL、数据表和图表；每种内容独立呈现，避免把所有内容塞进一段 Markdown。
- **多轮上下文**：消息与查询结果绑定到会话和资源；追问时明确继承哪些上下文，切换资源或会话时正确重置。
- **数据配置表单**：从数据库元数据生成字段配置表，处理加载、空状态、类型变更、校验和未保存提示。
- **图表与表格联动**：根据返回字段推断合适图表；用户切换图表时保留相同查询结果，图表不适用时给出明确限制。
- **可解释性呈现**：把“问题理解 → 查询条件 → SQL → 结果”串起来，支持折叠/展开与错误定位。

### 6.2 面试讲解顺序

1. 先讲一次完整使用场景和系统边界：用户选表提问，模型不直接碰数据库。
2. 再讲前端如何管理异步对话状态、澄清和多类型结果块。
3. 再讲语义配置如何约束指标、字段和默认聚合，减少模型猜测。
4. 最后讲查询安全：服务端校验、只读账号、超时/行数限制和可追溯 SQL。

## 7. 验收清单

- 管理员能测试数据库连接、浏览表、预览数据，并发布一张表为问数资源。
- 管理员能配置字段角色/别名/单位/聚合、推荐问题和模型服务；模型测试有成功与失败反馈。
- 用户能对选定资源问出一个聚合问题，看到查询条件、SQL、结果表和对应图表。
- 一个存在歧义的问题会进入澄清；用户确认后才执行，答案显示确认后的条件。
- 同一会话的追问能引用上文；切换会话不会复用不相关上下文。
- 非只读 SQL、未配置表/字段和超限查询会被拒绝；数据库凭据不会出现在接口响应或页面。
- 无数据、连接失败、SQL 失败和模型失败能被区分并显示恢复建议。
