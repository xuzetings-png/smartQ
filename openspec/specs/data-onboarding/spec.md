# data-onboarding Specification

## Purpose

管理 MySQL 数据源、表结构、问数资源字段语义、固定指标口径、发布状态和结构复核。

## Requirements

### Requirement: 管理并发布问数资源

系统应允许管理员查看资源列表与详情、编辑资源草稿和字段语义，并在校验通过后发布。命名指标和推荐问题属于可选配置；资源至少需要一个允许问数的指标或维度字段。资源草稿不会提供给问数用户；只有已发布且未待复核的资源可以选择。

#### Scenario: 查看资源列表和详情

- WHEN 管理员打开问数资源页面并选择一个资源
- THEN 系统显示资源名称、来源表、状态、字段配置和推荐问题
- AND 页面不返回或展示数据库连接密码

#### Scenario: 编辑资源草稿

- WHEN 管理员修改资源名称和字段语义并保存
- THEN 系统保存完整配置并将资源置为草稿状态
- AND 草稿不会作为可问资源提供给问数用户

#### Scenario: 一键发布默认配置

- WHEN 管理员点击“一键发布”
- THEN 系统将资源状态改为已发布
- AND 保存当前表单配置后在同一操作中完成发布
- AND 不要求管理员预先配置命名指标或推荐问题
- AND 已发布资源可供本地演示的问数用户选择

#### Scenario: 没有命名指标时仍可发布

- WHEN 资源至少有一个允许问数的指标或维度字段，但没有命名指标
- THEN 系统允许资源发布
- AND 后续问数可以基于开放字段规划受控聚合

#### Scenario: 拒绝发布不可问资源

- WHEN 所有字段都被关闭或设置为“不参与问数”
- THEN 系统拒绝发布并指出需要修正的字段
- AND 资源保持未发布状态

#### Scenario: 拒绝无效的可选业务口径

- WHEN 管理员配置了命名指标，但指标字段、聚合方式或固定过滤条件无效
- THEN 系统拒绝发布并指出需要修正的配置
- AND 资源保持未发布状态

### Requirement: 配置字段含义

系统应允许管理员为每个字段配置业务名称、描述、指标或维度角色、单位、默认聚合方式、同义词和是否允许问数，并提供批量设置可问状态的操作。标记为不可问的字段必须从资源的可问范围中排除。

#### Scenario: 配置指标和维度

- WHEN 管理员将字段设为指标或维度并保存
- THEN 系统持久化字段语义、单位、同义词和默认聚合方式
- AND 指标的默认聚合只能从该字段类型允许的聚合方式中选择

#### Scenario: 隐藏不允许提问的字段

- WHEN 管理员将某个字段设为不可问
- THEN 该字段仍保留在资源结构中供管理员查看
- AND 该字段不属于已发布资源的可问字段

#### Scenario: 批量开启可问字段

- WHEN 管理员点击“全部开启”
- THEN 所有角色为指标或维度的字段允许问数
- AND 角色为“不参与问数”的字段保持关闭
- AND 操作只更新尚未保存的配置表单

#### Scenario: 批量关闭可问字段

- WHEN 管理员点击“全部关闭”
- THEN 所有字段均设置为不允许问数
- AND 字段名称、角色、描述、单位、默认聚合方式和同义词保持不变
- AND 操作只更新尚未保存的配置表单

### Requirement: 为新建资源自动设置字段默认值

系统应在基于 MySQL 表创建资源时，根据字段注释、字段类型、标识符特征和敏感字段名称规则生成默认字段配置；管理员可以在发布前调整这些配置。

#### Scenario: 使用新资源默认字段配置

- WHEN 管理员基于 MySQL 数据表创建问数资源
- THEN 系统使用字段注释作为默认业务名称，注释为空时使用物理字段名
- AND 系统按字段类型推断指标或维度，并将标识符字段归为维度
- AND 命中内置敏感字段名称规则的字段默认设为“不参与问数”并保持关闭
- AND 其他字段默认允许问数

### Requirement: 配置命名指标和不可覆盖的固定口径

系统应允许管理员为资源定义命名指标，包括指标名称、数值字段、聚合方式、同义词和零到多个固定等值过滤条件。固定过滤条件只能引用已启用的维度字段；枚举字段的过滤值必须来自数据库已知枚举值。后续问数必须严格遵守已发布命名指标的固定口径，用户问题不能覆盖或移除这些过滤条件。开放数值字段允许在后续问数规划中使用受控聚合，但不得因此改变已发布命名指标的定义。

#### Scenario: 配置销售额指标

- WHEN 管理员配置“销售额”使用 `amount` 字段的 `SUM` 聚合，并固定 `status=paid`
- THEN 系统保存该命名指标及其固定口径
- AND 后续引用“销售额”的查询必须保留 `status=paid`

#### Scenario: 拒绝由问题覆盖固定口径

- WHEN 后续用户询问“包含退款的销售额”
- THEN 系统不得修改“销售额”的固定过滤条件
- AND 应要求用户改问可开放字段对应的其他指标，例如“订单金额”

#### Scenario: 允许开放字段受控聚合

- WHEN 后续用户询问开放数值字段的平均值，且未引用口径固定的命名指标
- THEN 系统可按受控聚合规则规划 `AVG` 查询
- AND 该临时聚合不会修改任何命名指标配置

#### Scenario: 拒绝无效指标配置

- WHEN 管理员将命名指标关联到不可问或非数值字段，或固定过滤引用不可问的非维度字段
- THEN 系统拒绝保存或发布，并指出无效的字段配置

### Requirement: 配置推荐问题

系统应允许管理员为资源保存零到四条推荐问题，并按配置顺序展示。

#### Scenario: 保存推荐问题

- WHEN 管理员编辑并保存有效的推荐问题列表
- THEN 系统按输入顺序保存问题并在资源详情中返回
- AND 空白、重复或超过四条的问题列表不能保存

### Requirement: 复核数据库表结构变化

系统应允许管理员刷新资源对应的数据库表结构。发现字段新增、删除或类型变化时，应保存待复核结构并将资源标记为待复核；待复核资源不得发布或供问数使用。

#### Scenario: 发现结构变化

- WHEN 管理员刷新资源结构且当前结构摘要与已确认摘要不同
- THEN 系统展示新增、删除和变化字段
- AND 将资源标记为待复核并保留当前字段配置

#### Scenario: 接受变更后的结构

- WHEN 管理员确认待复核结构
- THEN 新字段以不可问状态加入，已删除字段从资源字段配置中移除，现有字段保留可复用的语义配置
- AND 资源回到草稿状态，必须重新通过发布校验

#### Scenario: 结构没有变化

- WHEN 管理员刷新资源结构且结构摘要未变
- THEN 系统报告结构无变化并保留资源状态和现有配置

### Requirement: 保留演示数据库中文结构说明

系统初始化本地演示 MySQL 时应使用 utf8mb4 解析 SQL 文件，并在数据源结构信息中正确保留中文表说明和字段说明。

#### Scenario: 初始化演示数据库

- WHEN MySQL 容器首次执行演示建表脚本
- THEN 数据源管理页显示正确的中文表说明“合成订单数据”
- AND 表字段说明以正确中文保存并可供资源配置读取

#### Scenario: 读取数据源结构

- WHEN 管理员连接演示数据库并读取表结构
- THEN API 返回的中文表说明与字段说明不得出现字符集乱码

### Requirement: 配置本地演示数据库端口

系统应允许用户通过 `MYSQL_HOST_PORT` 配置 Compose 演示 MySQL 的本机访问端口；未设置时应使用 3306。演示数据灌入脚本必须使用相同端口。API 和灌数脚本必须能够从仓库根目录读取 `.env.local`。`SMARTQ_DEMO_DATE` 留空时，灌数脚本应使用当天日期。

#### 场景：使用默认端口

- WHEN 用户没有设置 `MYSQL_HOST_PORT`
- THEN 演示数据库通过本机 3306 端口访问
- AND 样例数据脚本连接本机 3306 端口
- AND API 与灌数脚本均读取仓库根目录 `.env.local`

#### 场景：默认端口已被占用

- WHEN 用户将 `MYSQL_HOST_PORT` 设置为其他可用端口，例如 3307
- THEN Compose 将该本机端口映射到容器 MySQL 的 3306 端口
- AND 样例数据脚本通过配置的本机端口连接数据库
- AND 用户可在数据源管理页填写相同端口完成连接
- AND API 与灌数脚本均读取仓库根目录 `.env.local`
