# 任务清单：learning-mvp

## 范围与规格

- [x] 将 PRD 收敛到学习项目的问数端到端闭环。
- [x] 定义数据库接入和字段语义场景。
- [x] 定义提问、澄清、多轮对话、结果呈现和安全查询场景。
- [x] 定义模型和业务术语配置场景。
- [x] 对照面试演示目标复核精简后的功能边界。

## 已确认的技术选型

- [x] 采用本地浏览器演示，前端使用 Vite + React + TypeScript。
- [x] 使用 Ant Design、Ant Design Charts 和 React hooks 管理前端状态。
- [x] API 使用 Node.js 24 LTS + TypeScript + Express。
- [x] 使用 pnpm workspace，包含 `apps/web`、`apps/api`、`packages/contracts`。
- [x] 使用 Docker Compose 在本地运行 MySQL 8.4 LTS；应用服务运行在宿主机。
- [x] 业务数据只读直连 MySQL；SmartQ 配置和历史记录存入 SQLite。
- [x] 使用阿里云百炼/通义千问、Zod 校验的 JSON 查询计划、服务端 SQL 编译和 SSE 阶段事件。
- [x] 使用页面内管理员/问数用户切换，不实现真实登录。
- [x] 评审并确认首轮 `design.md` 后开始实现；未决事项在进入相关功能前解决。

## 实施计划（开发中）

### 0. 项目和演示环境基础

- [x] 建立 Node 24 pnpm workspace、共享 TypeScript 配置、本地启动脚本、Vite 的 `/api` 代理和 Express 健康检查接口。
- [x] 配置 MySQL 8.4 Compose 服务、本机端口绑定、数据卷和健康检查；通过初始化 SQL 建立合成 `orders` 表和仅有 `SELECT` 权限的专用账号。
- [x] 建立 SmartQ 自身数据的 SQLite 迁移和存储层；用 AES-256-GCM 加密、解密凭据，主密钥从本地环境变量读取。
- [x] 编写中文根目录 README，说明首次启动、环境变量、数据库启动/停止/重置、演示账号和常见故障处理。

### 1. 数据源与问数资源配置

- [x] 实现一个数据库连接的测试、新建和更新、结构浏览、有界数据预览和凭据遮蔽（对应规格：`data-onboarding` 的连接成功/失败场景）。
- [x] 实现管理员端连接和表选择界面，覆盖连接中、加载中、无数据和错误状态（对应规格：`data-onboarding` 的连接场景）。
- [ ] 实现单表资源的新建和更新、字段角色/默认聚合/同义词、隐藏字段和推荐问题（对应规格：`data-onboarding` 的资源发布、字段配置、隐藏字段和推荐问题场景）。
- [ ] 实现结构刷新；若已暴露字段被修改或删除，将资源标记为 `needs_review`（对应规格：`data-onboarding` 的结构变化场景）。

首个可交付纵向切片为“数据源管理页”：本地应用骨架、MySQL 演示环境、连接测试/保存、表结构浏览、20 行样例预览和创建草稿资源。首个切片完成后继续资源语义配置页，再做模型配置与问数工作台。

### 2. 模型与语义配置

- [ ] 实现百炼兼容的模型设置、密钥遮蔽、连通性测试和默认模型启用（对应规格：`admin-configuration` 的模型测试成功/失败场景）。
- [ ] 实现资源范围内的业务术语配置，并把术语与同义词加入查询规划上下文（对应规格：`admin-configuration` 的业务术语场景）。
- [ ] 实现样例问题的查询计划预览和校验，不执行 SQL（对应规格：`admin-configuration` 的样例问题调试场景）。
- [ ] 实现相应的管理员表单和计划预览面板（对应规格：`admin-configuration`）。

### 3. 安全查询规划与执行

- [ ] 在 `packages/contracts` 中定义查询/澄清计划及 SSE 事件的共享 Zod 结构。
- [ ] 只使用选中资源、可用字段、业务术语和有限会话上下文构造模型输入；拒绝无法解析的 JSON 或不合规计划。
- [ ] 仅编译单表 `SELECT`；标识符来自已保存的结构元数据并按规则引用，所有查询值均使用 MySQL 参数绑定。
- [ ] 通过专用只读 MySQL 账号执行；设置服务端行数和执行时间上限，并保存查询计划、SQL、结果元数据、拒绝和错误记录。

### 4. 对话 API 和问数界面

- [ ] 实现会话/消息持久化、追问上下文隔离，以及 `POST /api/conversations/:id/turns` SSE 接口。
- [ ] 实现取消处理、错误归一化和明确的问数状态：理解中、澄清中、执行中、成功、无结果、失败和已取消。
- [ ] 使用 React hooks/reducer 实现演示角色切换、资源选择、推荐问题、会话列表、对话输入、澄清交互和追问界面。
- [ ] 使用 `fetch`/`ReadableStream` 读取 POST SSE 响应；呈现查询条件、生成 SQL、有界 Ant Design 表格，并支持切换适用的 Ant Design Charts 图表。
- [ ] 处理无结果、数据源/模型失败、计划不合规、流中断及重试/修改建议（对应规格：`questioning` 的澄清、进度/失败和空结果场景）。

### 5. 验收与 SDD 收尾

- [ ] 使用本地演示逐项检查三份增量规格中的场景，在验收记录中标注通过/未通过及需要的规格变更。
- [ ] 实施中若发现新事实，先更新提案、规格、设计和任务，再继续受影响的实现任务。
- [ ] 所有验收场景通过后，将完成的规格增量合并至 `openspec/specs/` 并归档本变更。
