# 方案提案：学习型问数产品首个纵向切片

## Why（背景与目标）

需要用最小的功能范围讲清楚小 Q 问数的产品价值和实现难点，重点展示前端如何处理数据配置、自然语言对话、多轮状态和结构化结果。项目用于学习和面试展示，不以企业商业交付为目标。

## What Changes（变更内容）

实现一个单工作区的端到端闭环：连接一种数据库；将一张表发布为问数资源并配置字段语义；管理员配置一个默认模型；用户选择资源后提问；系统在歧义时澄清，执行受控只读查询，展示解释、SQL、表格和基础图表；用户可以在当前会话中继续追问。

## 本期范围

- 一个只读 MySQL 连接器并直连查询，一次问数只针对一张已配置表。
- 单表资源配置：字段名称/描述、维度或指标、单位、默认聚合、同义词和少量推荐问题。
- 一个默认模型服务的配置、密钥遮蔽和连通性测试。
- 桌面 Web 问数、澄清、多轮对话、结果表/基础图表、SQL 解释和简易会话历史。
- 服务端查询校验、只读连接和基础执行日志。

## 暂不纳入

多租户和企业级角色系统、细粒度行列授权、文件问数、跨表关联/多资源选表、语音/移动端、复杂企业知识库、模型路由、预测/归因、运营大盘、嵌入、完整 BI 报表和生产级运维。

## 成功标准

管理员能从数据库表创建一个可问资源；用户能通过自然语言得到可解释的查询结果；歧义和失败状态有清晰交互；数据库访问受到服务端约束；开发者能沿规格场景演示并讲解每一步。

## 已确认的选型与实施前提

- 已确定本地浏览器演示、Vite + React + TypeScript、Ant Design/Ant Design Charts、Node 24 + Express、pnpm workspace、MySQL 8.4 LTS（Docker Compose，只读直连）、SQLite、百炼/Qwen、SSE、JSON 查询计划和页面内演示角色切换。
- 技术设计与按数据层/API/页面拆分的实现任务已补齐；整体设计评审通过后开始实现。
