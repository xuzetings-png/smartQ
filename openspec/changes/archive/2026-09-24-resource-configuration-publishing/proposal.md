# 问数资源配置与发布

## Why

当前系统可以从 MySQL 数据表创建资源草稿并保存字段快照，但资源配置入口仍是占位页。字段全部默认不可问，管理员无法补充业务语义或发布资源，问数用户也没有可选的已发布资源。

## What Changes

- 提供问数资源列表、详情、字段语义、业务指标规则和推荐问题配置。
- 增加发布校验；只有配置有效的资源可以发布为可问状态。
- 提供结构刷新与复核，检测新增、删除和类型变更，待复核期间暂停资源使用。
- 通过版本化 SQLite 迁移持久化指标规则、推荐问题和待复核结构。

## 不在范围内

- 不实现模型配置、业务术语、计划调试和问数工作台；这些属于后续 OpenSpec 增量。
- 不提供跨表资源、角色授权或真实用户登录。
- 不自动推断企业业务口径；管理员负责确认命名指标、聚合方式和固定过滤条件。
- 不在本增量执行自然语言问数；但配置的数据模型必须保证后续规划器无法覆盖命名指标的固定口径。

## 成功标准

- 管理员能打开并编辑已创建的资源草稿，保存字段含义、命名指标规则与最多 4 条推荐问题。
- 命名指标可配置字段、聚合方式、同义词和固定过滤条件；“销售额”可以表达为 `SUM(amount)` 且固定 `status=paid`。
- 有至少一个有效可问命名指标的资源可以发布；不合规配置会明确指出问题并保持未发布。
- 结构变化可被检测并标记为待复核；管理员确认新结构后可重新配置并发布。
- 已发布资源列表和详情通过 API 返回，配置不会暴露数据库凭据。
- OpenSpec、零诊断门禁和回归用例通过。
