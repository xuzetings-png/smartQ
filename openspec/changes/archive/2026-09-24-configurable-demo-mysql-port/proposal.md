# 提案：支持配置本地演示 MySQL 端口

## 背景

本地电脑可能已有 MySQL 服务占用 3306，导致 SmartQ 的 Compose 演示库无法启动。当前 Compose 端口映射和样例数据灌入脚本都固定使用 3306，用户无法通过修改连接表单绕过冲突。

## 目标

- 允许通过 `.env.local` 为 Compose 演示库配置本机端口。
- 样例数据脚本使用同一个端口连接演示库。
- API 和灌数脚本从仓库根目录读取 `.env.local`，确保连接凭据及加密密钥生效。
- 可选演示日期留空时按当天生成数据。
- 文档说明如何在默认端口被占用时完成首次使用。

## 不在范围内

- 不改变数据库容器内部端口、数据结构或问数行为。
- 不自动探测并选择端口。
- 不修改数据源管理页的默认端口；用户填写的端口应与 `.env.local` 一致。

## 验收标准

- 未设置端口时 Compose 和灌数脚本继续使用 3306。
- 设置 `MYSQL_HOST_PORT=3307` 时，Compose 将本机 3307 映射到容器 MySQL 3306，灌数脚本连接本机 3307。
- API 与灌数脚本均能读取仓库根目录的 `.env.local`。
- `.env.local` 中 `SMARTQ_DEMO_DATE` 为空时灌数脚本使用当天日期。
- 首次使用文档指出页面端口需与 `MYSQL_HOST_PORT` 一致。
