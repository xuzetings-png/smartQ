# 技术设计：修复演示 MySQL 中文注释编码

## 根因证据

- `01-schema.sql` 中“合成订单数据”的源文件字节是正确 UTF-8。
- MySQL 初始化连接的 `character_set_client`、`character_set_connection` 和 `character_set_results` 均为 latin1。
- `information_schema` 中表和字段注释的原始字节已是错误转码后的内容；数据源 API 将该值原样返回。
- 业务行中的中文由 mysql2 使用 utf8mb4 写入，因此预览数据正常，只有初始化 DDL 中的注释乱码。

## 实现方案

- 在 `demo/mysql/init/01-schema.sql` 开头执行 `SET NAMES utf8mb4;`，确保后续建库建表和中文注释使用统一字符集。
- 通过 Vitest 检查字符集声明位于建表语句前，锁定初始化脚本的关键约束。
- 对已创建的本地演示库使用 utf8mb4 连接，修复表说明和全部字段说明；不删除或重建数据卷。
- 使用原有数据源 API 精确断言返回的订单表说明为“合成订单数据”，并确认字段注释字节正确。

## 风险控制

- 当前演示库使用已知的订单表定义，修复字段说明时保留列类型、可空性、自增属性、字符集、索引和数据。
- 新初始化用户通过 SQL 文件获得修复；已存在的数据卷不会自动重新执行初始化脚本，因此当前本地库需要一次性元数据修复。
